# План поддержки Waveshare ESP32-S3-Touch-LCD-7B

Статус: ожидаем реальное устройство для проверки определения модели и первичного запуска.

Ссылки:

- [ESP32-S3-Touch-LCD-7B](https://www.waveshare.com/esp32-s3-lcd-7b.htm?sku=31726)
- [Waveshare Wiki](https://docs.waveshare.com/ESP32-S3-Touch-LCD-7B)

## Цель

Поддерживать обычный ESP32-S3-Touch-LCD-7 и новый 7B одной кодовой базой. В
идеальном варианте одна прошивка определяет модель при загрузке, выбирает
правильные параметры RGB-панели и строит интерфейс под доступное разрешение.

Текущий дисплей 7 должен остаться визуально и функционально неизменным.

## Известные различия

| Параметр | ESP32-S3-Touch-LCD-7 | ESP32-S3-Touch-LCD-7B |
| --- | --- | --- |
| Разрешение | 800x480 | 1024x600 |
| Интерфейс LCD | RGB565 | RGB565 |
| Flash / PSRAM | 16 MB / 8 MB | 16 MB / 8 MB |
| Touch | GT911, I2C | 5-point capacitive touch, I2C |
| Дополнительно | базовое управление подсветкой | регулируемая подсветка, контроль батареи |

Основные RGB GPIO и I2C GPIO 8/9 у плат совпадают, но тайминги панели, управление
питанием/подсветкой и touch reset нужно брать из официальных примеров именно 7B.

## Определение модели

RGB-панель не предоставляет EDID, поэтому разрешение нельзя узнать через LCD
драйвер: `getFrameWidth()` вернёт размер, с которым драйвер уже был создан.
Профиль нужно выбрать до инициализации RGB-панели.

Первый кандидат для автоматического определения touch-версии 7B:

1. До запуска LCD инициализировать I2C на GPIO 8/9.
2. Прочитать product ID и нативные X/Y limits из конфигурации GT911.
3. Значение 800x480 трактовать как обычный 7, 1024x600 как 7B.
4. Проверить на обеих реальных платах, что Waveshare не перезаписывает эти поля
   при инициализации и что значения стабильны после холодного старта.

Для версии без touch и на случай неудачного probe предусмотреть явный профиль
`auto / 7 / 7B` в NVS и веб-настройках. Если надёжного аппаратного признака не
найдётся, выпускать два бинарника из одной кодовой базы вместо рискованного
автоопределения.

## План реализации

1. Снять конфигурацию официального примера 7B: RGB timings, PCLK, polarity,
   bounce buffer, touch transform, GPIO expander, питание и подсветку.
2. Добавить `DisplayProfile` с моделью, разрешением, RGB timings, touch transform
   и параметрами стабильности. Убрать размеры панели из глобальных compile-time
   констант приложения.
3. Выполнять probe до создания RGB bus/LCD. Печатать выбранную модель,
   разрешение и источник выбора (`probe`, `NVS`, `build default`) в boot log.
4. Проверить, допускает ли `ESP32_Display_Panel` выбор профиля во время работы.
   Если текущий `Board` остаётся compile-time, создавать RGB LCD и touch из
   runtime-конфигурации напрямую либо собирать два target-бинарника.
5. Перевести layout, framebuffer screenshot, touch bounds, label solver и карту
   на фактические `screenWidth/screenHeight`.
6. На первом запуске 7B не увеличивать шрифты и иконки. Сохранить их текущий
   физический размер, использовать дополнительную площадь для большей карты,
   более широкой правой панели и дополнительных строк списка.
7. Оставить соотношение областей примерно 65/35, но вычислять точный разделитель
   из ширины экрана и минимальной ширины строк списка.
8. Пересчитать PSRAM: два framebuffer 1024x600 требуют примерно 2.46 MB вместо
   1.54 MB. Отдельно проверить память map cache и XIP high-performance SDK.
9. Для 7B начать с официальных timings, conservative PCLK и RGB bounce buffer.
   Настраивать PCLK и размер bounce buffer только после стабильного вывода
   тестовой сетки и длительного теста с Wi-Fi/картами.

## Проверка на устройстве

- Запустить отдельную probe-прошивку и сохранить I2C scan, GT911 ID/config и
  данные GPIO expander для обеих моделей.
- Проверить холодный старт, reset и загрузку после полного отключения питания.
- Проверить одноцветные экраны, тестовую сетку, отсутствие wrap/drift и реальные
  границы 1024x600.
- Проверить четыре угла touch, удержание для setup и быстрые тапы при пустом
  радаре.
- Проверить boot screen, карту всех range, ADS-B, список, треки и screenshot BMP
  с фактическим разрешением.
- Провести стресс-тест Wi-Fi, загрузки тайлов, NVS и серии screenshots; затем
  оставить дисплей минимум на несколько часов.
- Собрать и проверить оба профиля. Изменения для 7B не должны менять layout,
  timings и стабильность обычного 800x480 дисплея.

## Критерий готовности

Одна прошивка предпочтительна только при детерминированном определении модели до
инициализации LCD. При любой неоднозначности приоритетом остаётся безопасный
ручной профиль или два подписанных бинарника `7` и `7B`.
